## 目标

该 skill 用于防止子智能体：
- 静默结束
- 空响应结束
- 只调用工具不返回
- 因“遇阻即停”而误解成“直接不说话”

你的任务不是沉默，而是**用一次终局返回明确交代状态**。

## 硬规则

1. 你必须始终向 Master 返回且只返回一次。
2. 该次返回必须是**终局返回**。
3. 允许的终局状态只有：
	- `PASS`
	- `BLOCKED`
	- `FAIL`
	- `NEEDS_USER_DECISION`
4. **绝不允许静默结束、空响应、只调用工具不返回消息。**
5. 若你负责文件化产物：
	- 在可行时，先写入产物
	- 再返回终局消息
6. 若由于工具失败导致连产物都无法落盘：
	- 也必须返回终局消息
	- 并明确说明：
		- 卡在哪里
		- 为什么不能继续
		- 下一步需要谁处理

## 状态语义

### `PASS`
用于：
- 已按当前职责完成工作
- 必要产物已写入或已明确无需产物
- 可以安全交给下一阶段

### `BLOCKED`
用于：
- 契约缺失
- scope 不足
- 文件缺失
- 上游依赖未完成
- 路径不存在
- 研究与实际结构冲突
- 工具失败导致当前阶段无法继续

### `FAIL`
用于：
- 你承担的是评审/验证角色
- 并且发现了明确不通过的问题
- 或执行结果明确失败

### `NEEDS_USER_DECISION`
用于：
- 多方案取舍
- 高风险选择
- 是否接受 breaking change
- 是否继续某条方案
- 需要用户目视确认 UI 效果

## 终局返回最少应包含

- `Status`
- `Artifact Path` 或 `None`
- `Summary`
- `Next Step` 或 `Next Agent`

如果你的职责要求固定返回格式，则在该格式中显式携带以上信息。

## 阻塞时的行为

阻塞不是沉默。
阻塞时你必须：
1. 尽量记录阻塞原因到允许写入的产物
2. 明确指出缺失项
3. 指出不能继续的原因
4. 指出下一步需要谁介入

## 工具失败时的行为

即使发生以下情况：
- read 失败
- edit 失败
- search 失败
- terminal 命令失败
- agent 调用依赖缺失

你也不得静默结束。
你必须返回：
- `BLOCKED` 或 `FAIL`
- 并说明：
	- 哪个工具失败
	- 失败对当前阶段的影响
	- 是否可重试
	- 建议谁处理

## 返回前自检

在结束前必须自检：
- 我是否已经返回且只返回一次？
- 我的返回是否明确包含终局状态？
- 若阻塞，我是否写清缺失与下一步？
- 若有产物职责，我是否已落盘或明确说明无法落盘？
- 我是否避免了静默结束？

若任一答案为“否”，不得结束。
