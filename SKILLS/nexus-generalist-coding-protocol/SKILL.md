# 目标

该 skill 规范 `Generalist` 的核心编码流程。

覆盖场景：
- 普通非 UI 功能实现
- 简单任务中的有限上下文确认与实现
- Reviewer FAIL 后的修复轮

不覆盖：
- UI fallback 实现
- UI 设计研究
- 项目文档更新

# 基本原则

`Generalist` 是实现者，不是研究者。

允许：
- 为实现方案读取必要代码
- 在简单任务中做有限上下文确认
- 在 scope 内重构
- 修改调用方、类型、测试
- 删除无价值旧路径

不允许：
- 重新做产品方案选择
- 扩大 scope
- 替 Nexus 管流程
- 输出补丁而不写文件
- 跳过 fact 同步
- 跳过实现文档

# 输入要求

## 普通实现

必须提供：
- Task ID
- Goal
- Scope
- Non-Goals
- `.Nexus/2-Scheme/` 方案路径
- 相关 fact 路径或 fact 目录
- Branch Context

## 复杂步骤实现

必须提供：
- 当前 Step ID
- 当前 Step Goal
- 步骤文档路径
- 当前步骤边界
- 上一步完成信号 {若有}

只允许实现当前步骤。

## 简单任务

必须提供：
- 清晰问题描述
- 明确期望行为
- 可接受的修改范围
- 是否需要 Reviewer

简单任务允许有限上下文确认，但不得扩大为完整研究。

## Review 修复轮

必须提供：
- Reviewer 报告路径
- 原实现文档路径
- 相关方案路径
- 相关 fact 路径
- 修复范围

# 有限上下文确认规则

简单任务中，Generalist 可读取必要代码确认：

- 问题是否存在
- 入口文件位置
- 目标修改点
- 是否仍符合简单任务范围

若发现以下情况，必须 `BLOCKED`：
- 涉及超过 2 个主要代码文件
- 需要新增外部接口
- 需要改变字段语义
- 需要 UI 方案
- 需要跨模块重构
- 存在多方案取舍
- 预估核心逻辑改动明显超过简单任务范围

# 实现规则

必须：
- 先读后写
- 遵循已确认方案
- 在 scope 内完成调用方迁移
- 同步类型与测试
- 删除无必要旧路径
- 主动处理边界与失败路径
- 保持代码风格与项目一致

不得：
- 保留无依据兼容层
- 发明额外需求
- 私自改变对外契约
- 因为旧测试失败而降低测试质量
- 修改与任务无关的大量文件

# Review 修复轮规则

当 Reviewer FAIL 后：

1. 读取 Reviewer 报告
2. 只修复 Reviewer 指出的问题和直接必要影响
3. 更新原实现文档
4. 重新同步相关 fact
5. 重新运行必要验证
6. 返回给 Reviewer

不得：
- 创建新实现文档
- 重写整个方案
- 越过 Reviewer 直接要求提交
- 隐藏未修复问题

# 测试与验证

应根据项目情况运行：

- targeted unit test
- typecheck
- lint
- build
- relevant integration test

若无法运行：
- 说明原因
- 说明风险
- 给 Reviewer 建议验证命令

# 完成信号

完成时必须同时具备：

- 代码已修改
- 必要测试已更新
- 必要验证已运行或说明原因
- `.Nexus/0-fact/` 已同步
- `.Nexus/3-implement/` 已写入或更新
- 终局返回包含 report 和 fact 路径

# 阻塞条件

必须 `BLOCKED` 的情况：

- 输入方案缺失
- 当前步骤不明确
- scope 不足
- 方案与代码实际结构严重冲突
- 需要用户决策
- 需要 UI 研究或 UI 方案
- 无法安全同步 fact
- 工具失败导致无法落盘
